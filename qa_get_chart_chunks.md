## 3. Дефекты, найденные и исправленные в ходе QA

1. **Транзитная глава вместо натальной.** `Sun_in_House_10` возвращал «2.2.10. ТРАНЗИТ СОЛНЦА ЧЕРЕЗ X ПОЛЕ ГОРОСКОПА» вместо «2.3.10 Солнце в X поле гороскопа»: оба чанка имели tier 2, выбор решал `book_id`. Исправлено: при равном tier натальные разделы идут раньше транзитных (`Candidate.is_transit`), тест `test_lookup_prefers_natal_sections_over_transits`.
2. **Вводящий в заблуждение счётчик разделов.** «Найдено разделов: 897» было суммой совпадений с повторами. Теперь печатаются два числа: точные совпадения (с повторами) и уникальные `chunk_id` в выборке.
3. **Невоспроизводимость окружения.** `requests`, `timezonefinder`, `tzdata` не были объявлены в `pyproject.toml`/`uv.lock` — на чистом окружении этапы 1–2 упали бы. Добавлены, `uv lock` обновлён, `uv sync` сверен.

## 4. Пересборка метаданных (выполнена)

Причина: точный роутинг возвращал чужие статьи, потому что теги извлекались из текста чанка, а не из заголовка раздела.

Что изменено в `src/chunking/tags.py`:

* метаданные читаются **только из заголовка раздела** (текст — лишь для определения языка); случайные упоминания планет в абзаце больше не создают тег;
* добавлены `planet_b`, `sign_b`, `house_b` — второе тело пары («ВЕНЕРА – УРАН») и второй знак/дом («Восходящий Лунный Узел в Водолее. Нисходящий… во Льве»);
* «Лунный Узел» больше не тегируется как Луна: `NorthNode`/`SouthNode` распознаются по «Восходящий/Нисходящий Лунный Узел»;
* добавлен флаг `is_transit` (1239 чанков);
* аспект извлекается только если назван в заголовке (в корпусе таких нет — `aspect=null` у всех, тег-шум убран).

Схема payload расширена (`planet_b`, `sign_b`, `house_b`, `is_transit`), добавлены индексы Qdrant. Пересборка выполнена `scripts/update_strategy_payloads.py --collections structural_xml` **без переэмбеддинга**: 4782/4782 чанков обновлено.

## 5. Оставшиеся ограничения (источник, не код)

1. **Тип аспекта не размечен в книге.** Ни один заголовок не содержит «трин/квадрат/оппозиция/секстиль»; аспектные главы называются по паре («МЕРКУРИЙ – САТУРН», «Аспекты Меркурия с Сатурном»). Роутер возвращает главу пары с `coverage="pair_chapter"` — это максимум точности, который даёт источник. Тип аспекта в ключе (`Mercury_Saturn_trine`) сохраняется для будущей разметки.
2. **5 элементов без статей:** `SouthNode_Venus_conjunction`, `NorthNode_Venus_opposition`, `Jupiter_SouthNode_conjunction`, `Jupiter_NorthNode_opposition`, `Moon_NorthNode_trine`. В корпусе всего 24 раздела про узлы — «узел в знаке» и «узел в доме»; глав про аспекты к узлам нет.
3. **Дубли корпуса:** `Sun_in_Leo` даёт 8 совпадений, из них три чанка с одинаковым заголовком «2.2.5. Солнце в знаке Льва» из разных `book_id`. Дедупликация книг — отдельная задача корпуса.
4. **Nominatim отдаёт административный центр** (55.6256, 37.6064), а не точные координаты; для протяжённых городов смещение может быть заметнее. Для точности есть `--lat/--lon`.

## 6. Прочие проверки

* Полный прогон pytest: **117 passed, 4 failed**. Падения существовали до изменений (baseline: 4 failed / 82 passed): `test_generator`, `test_indexing` (2), `test_strategies` (устаревший `meta_tags`). К этому пайплайну не относятся.
* Негативные сценарии: `--top 0` → exit 2; время со смещением таймзоны → exit 1 с понятным сообщением; несуществующий город → exit 1; неизвестный аргумент → exit 2.
* Режим ручной проверки: `--top 3` → 92 уникальных раздела (до пересборки), `structural_lookup.py --planet-sign Sun Leo --top 3` показывает 3 кандидата с tier-ранжированием.
* `--lat/--lon --timezone` корректно пропускают этапы 1–2 (0 мс).

## 7. Рекомендации

1. Оставить `--top 1` в продакшене, `--top 5` — для приёмки.
2. При добавлении новых книг пересобирать payload той же командой (`update_strategy_payloads.py --collections structural_xml`) — переэмбеддинг не нужен.
3. Если понадобится различать типы аспектов, потребуется отдельная книга/разметка: текущий корпус описывает пары, а не отдельные аспекты.
